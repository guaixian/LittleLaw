## 建议修复顺序（按风险排序）

### 第一批：安全类（可被主动利用）

1. **11-P0-1/P0-2** 更新器无校验执行 + 备份 Zip Slip——直接 RCE
2. **07-P0-1/P0-2/P0-3** 配对三连：tap MITM / TLS pinning 绕过 / 提交时序——E2E 信任链根基
3. **09-P0-1** 服务器身份自声明——冒充/删信箱/劫推送
4. **07-P1-5 + 08-P1-3** QR token 兼任长期会话密钥——泄露即永久失守

### 第二批：数据完整性

5. **06-P0-1/P0-2** 存储层两个数据丢失/瘫痪缺陷
6. **06-P1-3** 游标卡死（48h 离线 + 删消息即触发）
7. **08-P1-2** Base45 字节序（跨版本静默损坏）

### 第三批：功能正确性

8. **01** WebRTC 候选丢弃（远程模式总源头）
9. **03** 文件传输两条必败路径
10. **04** 消息状态语义
11. **10-P0-1** 桌面壳状态复用
12. **12** 在线状态闪跳（连接前误报在线 + 重试无上限）
13. **13** 解绑会话残留（补事件通知 + 删孤儿行 + 墓碑会话）
14. **14** 消息菜单（桌面标准右键菜单 + 图标统一）
15. **15** 头像（ImageCache evict + 本地事件 + 裁剪器）
16. **16** 存储布局（%TEMP% 敏感泄漏改道 dataDir/tmp + 便携模式 + Roaming→Local）

### 第四批：体验与加固

12. 02（配对时序）、05（发现层）、其余 P1/P2 按文档内顺序
